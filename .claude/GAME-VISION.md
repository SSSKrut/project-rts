# GAME-VISION — продуктовый план (2026-07)

Слой «что за игра» поверх `GAMEDESIGN.md`: там — модель управления и архитектурные принципы, здесь — опыт игрока, продуктовые фичи и их порядок. `ROADMAP.md` остаётся трекером фаз и синхронизируется с этим документом после закрытия открытых решений (§8). Документ написан «без оглядки назад»: сначала желаемая игра, затем привязка к готовому движку (§9).

## §1. Видение

Длинная персистентная операция **1v1 — человек против ИИ** — на большой карте эпохи холодной войны с комплексной и **разрушаемой инфраструктурой**. Игрок — командир: отдаёт намерения, доверяет исполнение тактическому ИИ юнитов, выигрывает информацией и позицией. Операция идёт игровые сутки и недели: день/ночь, снабжение и удары по инфраструктуре меняют условия боя — обесточенный город тонет в темноте, разрушенные мосты и ЛЭП отрезают подвоз и связность. Кампании нет: **операция и есть игра**. В перспективе карты строятся из спутниковых данных (DEM/Landsat/OSM), а состав сил измеряется валютой — ценность каждого юнита экономически ощутима.

## §2. Столпы

1. **Командир, не оператор.** Приказы-намерения с lifecycle, standing rules, RoE; юниты исполняют компетентно (Utility-ИИ, MicroPath, SurvivalInstinct). Микро — не геймплей; babysitting — баг.
2. **Информация — оружие.** FoW, сенсорные каналы, шкала заметности, контакты. Бой выигрывается разведкой и позицией. Карта — командная поверхность («что я знаю»), 3D — местность и верификация («что там есть»).
3. **Читаемый реализм.** Системы реалистичны по последствиям, но детерминированы и объяснимы: шкалы и конверты вместо скрытых кубиков, у каждого отказа приказа — видимая причина. Детерминизм — также фундамент replay-гейта и стенда обучения ИИ.
4. **Противник — главная фича.** ИИ, ведущий операцию и дающий отпор: скриптовый оперативный сначала, обучаемый верхний ярус потом. Нейросеть — только на верхних ярусах иерархии.

## §3. Сессия

Сессии длинные — 1–2 часа и больше, одна операция растягивается на много сессий (save/load — часть цикла, не утилита). Анатомия:

- **Брифинг** на 2D-карте: задача, свои силы, разведданные.
- **Расстановка**: deployment-зоны, предварительные приказы на паузе.
- **Операция**: активная пауза + компрессия времени; лулл (затишье, марши, подвоз) сжимается сильной компрессией, контакт возвращает 1×. Игровые сутки/недели на одной карте, день/ночь.
- **Сводки**: Timeline-панель как журнал операции; периодический «итог дня» (потери, расход, продвижение) вместо терминального разбора.

Открытые параметры ритма — §8 (О-1).

## §4. Продуктовые системы

- **Операция v0** — манифест сценария поверх карт-манифестов: силы сторон, deployment-зоны, задачи; условия завершения (О-3); бот v0 на SquadService; флоу брифинг → расстановка → бой.
- **Инфраструктура** — `PowerGrid` (генерация, подстанции, ЛЭП) как граф-ресурс; разрушаемые мосты / ж/д / ЛЭП = состояние рёбер графов + нав-реплан; blackout: обесточка → гаснут источники света → падает видимость в городе ночью.
- **День/ночь** — свет как множитель в детекте (Detection 2.0 lightMul); NVG = сенсорный канал, осветительные средства = расходники; рендер ночи через **view-mode** (читаемый командный режим), не через честную темноту с гаммой.
- **Снабжение** — расход (боеприпасы уже конечны) → подвоз грузовиками по дорожному графу → интердикция = разрез графа. Пехота без подвоза деградирует.
- **Техника** — общее ИИ-шасси из четырёх слоёв (Driver локомоция / Gunner per-weapon огонь / рефлексы Flee-SmokeAndReverse-FaceThreat / operational-интеграция), различия классов — данные `VehicleSpec` (грузовик / БТР / БМП / танк / ПТ-носитель). Кинематика, без Jolt (детерминизм-гейт).
- **ИИ-противник** — оперативный скриптовый (план операции, реакция на потери и удары по инфраструктуре), позже обучаемый верхний ярус на детерминированном стенде.
- **Экономика** — валюта для закупки сил / подкреплений; сохраняет ценность юнита, даёт меру потенциала. После того как операция v0 покажет ритм.
- **Спутниковые карты** — пайплайн DEM (SRTM/Copernicus) + покрытие (Landsat/Sentinel) + улицы и здания (OSM) → манифесты v2 («высоты из файла»); движок не меняется.

## §5. UI: принципы (исследование 2026-07) и бэклог

Принципы:

- **Карта = командная поверхность.** Полный паритет приказов на карте (глаголы, ghost, facing-drag). 3D сохраняет власть над интерьерами и вертикальностью (этажи, окна, траншеи) — наше законное исключение из жанрового правила.
- **LOS/range-превью из гипотетической точки** — фича №1 жанра: keyhold-оверлей «что видно и что достаёт отсюда» из курсора или планового вейпоинта. Обязан питаться тем же кодом, что сим (ContactSystem/visualMagnitude) — никакой параллельной математики превью.
- **Каждый отказ/затык приказа — локализованное событие**: балун на карте + строка event log + причина в Inspector (`TacticalOverride.Reason` — несущая; молчаливый блок AttackMove×HoldFire — закрыть этим же механизмом).
- **Ночь — view-mode**, ночные возможности — снаряжение (NVG-канал, осветительные).
- Именованные пресеты поведения первичны, матрица тумблеров — под капотом. ~6 «сплавленных» глаголов движения.
- Докинг остаётся (множитель для продвинутых) + 2–3 курируемых layout-пресета, reset одной клавишей, save/share именованных layout'ов.
- Иконки: один визуальный канал = одно состояние; per-category toggles; размещение над юнитом.

Бэклог UI-пасса:

- **Редактируемые маршруты (модель Sea Power).** Waypoint = Order-entity; перетаскивание = мутация OrderTarget (queued — свободно, InProgress — retarget). Классы маркеров из `OrderKindSpec`: свободные (NeedsTerrain) / привязанные к сущности (re-snap на валидную цель того же класса) / вычисляемые (валидация). Per-leg профиль движения = UI над готовым `OrderParamMovementProfile`. **Пер-отрядное ветвление** от общей точки (решение 2026-07-07); внутриотрядный сплит — в отложках. Предпосылки: DP-3 (OrderChain → массив), PlanOp/undo (хвост 18).
- Inspector как поверхность выбора: roster-card (статус + селекция + взаимодействие с отрядами). Подтверждено владельцем 2026-07-19: «нельзя выбрать юнитов, чтобы взять под контроль» — реальная боль, не гипотеза.
- **Стандартизация общего вида** (владелец, 2026-07-19: «слегка перегружен»): единая типографика/отступы/цветовые каналы по панелям, иерархия важнее плотности (урок SD2/Broken Arrow: перегруз лечится не удалением данных, а иерархией и тултипами).
- **EventLog — из Inspector в отдельное окошко** (владелец, 2026-07-19): свой leaf/floater по паттерну Formation editor (floating + workspace, общий синглтон); стыкуется с «журналом операции» из §3 и located-notifications из принципов.
- Именованная лестница подавления/морали, читаемая в двух местах (иконки над юнитом + карточка).
- One-gesture emergency verb (double-tap отход: дым + реверс/отрыв к своим) — тот же спек, что рефлекс техники SmokeAndReverse.
- Видимые нумерованные цепочки вейпоинтов для всех выделенных отрядов.

## §7. Жёсткие следствия (приняты)

- **Компрессия времени и «мир вне окна» — одна задача.** Лулл-компрессия 30–60× при 60 Hz тике невозможна с полной симуляцией большой карты ⇒ нужна упрощённая дальняя модель = data-residency (REFACTOR-PLAN WS-E ш.6), **поднимается из Phase 24** в средний план (дизайн при M2, реализация к M4).
- **Save/Load — продукт, не гейт**: операция на недели без сейва не играется.
- **Ночь без view-mode и LOS-превью — фрустрация, не тактика.** Оба инструмента обязательны до включения blackout-геймплея.

## §8. Открытые решения

- **О-1. Ритм времени:** игровые сутки ≈ сколько реального времени; профиль компрессии (макс. множитель, авто-сброс на 1× по контакту).
- **О-2. Масштаб карты v0:** город + окрестности, 4–8 км? Больше?
- **О-3. Конец операции:** набор задач / слом сил противника / бессрочная песочница.
- **О-4. Сторона игрока:** СССР / НАТО / обе симметрично.
- **О-5. Порядок M3↔M4:** инфраструктура до ИИ (богаче мир для ИИ) или ИИ до инфраструктуры (раньше «игра»).
