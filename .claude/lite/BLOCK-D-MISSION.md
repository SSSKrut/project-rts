# Блок D — Сценарий и победа

Статус: **M0 и M1 закрыты 2026-08-26.** Миссия грузится, силы приходят по
расписанию, оба условия победы считаются одной системой, итог — карточка с
числами, и всё это гоняется headless с вердиктом. Осталось M2: миссии,
сыгранные владельцем. Здесь игра впервые становится игрой: до
этого блока всё, что построено, нельзя было ни выиграть, ни проиграть.

Блок помечен в `PLAN.md` как **главный риск проекта** — не потому что он
сложный, а потому что это первое место, где станет видно, что миссия скучная.
Поэтому милестоуны устроены так, чтобы играбельность проверялась как можно
раньше и как можно дешевле.

---

## P-решения

**P1. Миссия ССЫЛАЕТСЯ на карту, а не содержит её.** `missions/<name>.json`
называет `map`, и карта остаётся переиспользуемой. Иначе каждая новая миссия
форкала бы мир, и правка рельефа разъезжалась бы по десятку файлов.

**P2. Силы приходят по расписанию, сущностями — тем же механизмом, что
`AirArrival`.** `ForceArrival` — наземный близнец: время, сторона, что именно,
где. **Стартовых сил как отдельного понятия нет** — это `atSec: 0`. Один
механизм на «что-то появляется в момент T», а не два, из которых один
называется «начальная расстановка».

**P3. Победа считается ОДНОЙ системой, владеющей часами миссии.** Оба условия
(держать N из M непрерывно T секунд; владеть большинством на момент истечения)
живут в одном месте, поэтому на вопрос «почему я выиграл» есть один ответ.
Разложить их по разным потребителям — верный способ получить два разных ответа.

**P4. Итог — это ЧИСЛА, а не слово.** Точки, потери, **время под связью**.
Последнее — стык с блоком A: миссия оценивает, насколько хорошо игрок держал
сеть, и это превращает связь из помехи в ресурс, за который есть смысл платить.

**P5. Миссия останавливает симуляцию, а не выходит из игры.** Мир замирает,
итог показывается поверх, ESC возвращает. Приказы после конца не принимаются:
результат, который можно доиграть, — не результат.

**P6. Миссия обязана гоняться headless и печатать вердикт.** Это не удобство, а
единственный способ ИЗМЕРИТЬ критерий закрытия («проходится обоими исходами»), а
не посмотреть на него. `-mission=<name> -run-ticks=N` печатает ту же строку
вердикта, что сцены, и уходит в гейт.

**P7. Никакого языка сценариев.** Манифест — данные: стороны, точки, силы,
победа. Всё условное («если игрок взял точку — прислать резерв») — это бот,
блок E. Триггеры в JSON превратятся в язык программирования за три миссии.

**P8. Миссия играбельна БЕЗ бота.** Силы противника приходят по расписанию и
держат свои точки; реактивный ярус даёт им драться, когда на них выходят.
Условие «владеть большинством на момент истечения» и есть условие проигрыша,
пока бот не появился. Если миссия скучна только из-за отсутствия бота — это
станет видно немедленно, и это ровно то, ради чего блок стоит перед E.

## Модель данных

```go
type Mission struct {          // ресурс, один на мир
    Name       string
    TimeSec    float32
    HoldPoints uint8           // сколько точек надо держать
    OfTotal    uint8
    ForSec     float32         // ...непрерывно, столько секунд
}

type MissionState struct {     // ресурс
    Elapsed    float32
    HoldSince  [FactionCount]float32  // 0 = не держит нужное число
    Outcome    MissionOutcome         // None | PlayerWin | PlayerLoss | Draw
    EndedAt    float32
    Held       [FactionCount]uint8    // точек у каждой стороны сейчас
    Losses     [FactionCount]uint16
    LinkedSec  float32                // время игрока под рабочей связью
}

type ForceArrival struct {     // сущность, как AirArrival
    At        float32
    Side      uint8
    Kind      ForceKind        // squad | vehicle
    Template  uint8
    Vehicle   VehicleKind
    At        WorldPos
}
```

Числа миссии живут в её манифесте, а не в `MODEL.md`: это содержание, а не
модель.

**`forSec: 0` означает «держать до конца».** Условие удержания тогда никогда не
срабатывает, и миссию решает только таймер по большинству. Это не край случая, а
единственный способ выразить ОБОРОНУ: с ненулевым `forSec` защитник, который
стартует владельцем всего, выигрывает раньше, чем атакующий доедет.

## Майлстоуны

**M0 — Манифест и силы. ✅**  `missions/<name>.json`, флаг `-mission`, загрузчик,
`ForceArrival` + система выпуска по образцу `AirTrafficSystem`. Точки берутся из
манифеста через уже готовый `SpawnControlPoint`.
*Проверка:* миссия загружается, силы обеих сторон появляются в свои моменты,
точки стоят там, где сказано.

**M1 — Победа и итог. ✅** `MissionSystem` последним в конвейере: он читает мир,
который произвёл весь остальной тик. Оба условия, `Outcome`, карточка итога
поверх замершего поля, headless-вердикт той же формы, что у сцен.

Проверка вышла не сценами, а самими манифестами — это честнее, потому что
проверяет тот же путь, которым пойдёт настоящая миссия. `scripts/mission_gate.sh`
гоняет каждую дважды и требует и одинакового вердикта, и побайтово одинакового
лога хешей:

| | |
|---|---|
| `test_hold` | **VICTORY** на 23 с: 3 с на захват двух точек + 20 с удержания |
| `test_timeout` | **DEFEAT** по таймеру: 1 точка против 2 |
| `crossroads` | **DRAW**: обе стороны держат по одной и никто не двигается |

Третья строка — это P8, подтверждённый с первого запуска: без бота и без игрока
миссия честно кончается ничьёй. Ровно та проверка, ради которой блок D стоит
ПЕРЕД E.

**M2 — Две настоящие миссии** на существующих картах: `crossroads` (наступление,
три точки, hills) и `ridge_hold` (оборона двух точек против волн, valley).
Осталась игра владельцем — числа их уже держат, но интересность числом не
меряется.

## Критерии закрытия

1. Миссия проходится от начала до конца **обоими исходами**, и оба измерены
   headless, а не на глаз.
2. Итог читается без объяснений: точки, потери, время под связью.
3. Оба гейта зелёные; манифест миссии переживает save/load.
4. После конца миссии приказы не принимаются, и мир не двигается.

---

## Что НЕ делаем в этом блоке

- **Триггеры и скрипты** (P7).
- **Кампанию, цепочку миссий, сохранение прогресса** — заморожено в `GAME.md`.
- **Брифинг, цели текстом, диалоги.** Цель — это условие победы, и оно одно.
- **Подкрепления по запросу игрока.** Расписание — данные; запрос — решение,
  то есть бот.
- **Редактор миссий.** JSON правится руками, как карты.
