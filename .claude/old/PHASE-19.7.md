# PHASE-19.7 — Attention & Map Tools (UX-выводы из Sea Power)

Статус: **M1-M5 реализованы 2026-08-09; ждут owner-плейтеста.**
Гейты на финальном билде: replay_baseline 55/55 IDENTICAL + replay_gate PASS,
saveload OK, `go test ./ui ./core .` зелёные. Что разошлось с планом — в
разделе «Отклонения от плана» внизу.
Источник — сравнительный анализ `.claude/SEA-POWER-INTERFACE.md` (2026-08-09):
по командной грамматике и оконному менеджеру мы впереди, но у Sea Power целиком
закрыт «менеджмент внимания на длинной дистанции» (высокая компрессия времени +
авто-замедление на событиях + звуковой событийный канал), а у нас из трёх
компонентов нет ни одного. Наша концепция длинных 1v1-операций
(`project_game_vision`) приведёт ровно к их профилю игры: часы марша — минуты
боя. Плюс два дешёвых инструмента карты (линейка, click-to-fly) и карточка-ТТХ.

Рамка: **фаза не трогает сим.** Всё — frame-side (input / UI / audio / TimeScale).
Replay- и saveload-гейты обязаны пройти бит-идентично; сдвиг хеша = что-то
протекло в сим = красный флаг, а не «перезапишем базлайн».

## P-решения

**P1. Компрессия и авто-реакция — один пакет.** Скорости выше 8× не
существуют без матрицы авто-реакции. Урок Sea Power прямой: 100× без
авто-замедления = пропущенный первый контакт. Порядок майлстоунов это
кодирует: M1 (матрица) раньше M2 (16×/32×), и M2 не мержится без M1.

**P2. Один поток событий.** Авто-реакция читает тот же `EventLog`, что кормит
пинги и лог-панель. Никакой второй шины событий. Скан — раз в кадр после
`Advance` (frame-side), по индексу головы кольца; за кадр берётся максимальная
severity из новых записей. `EventEntry.Pos` уже лежит в кольце — click-to-fly
использует его же.

**P3. Авто-реакция понижает, игрок повышает.** Матрица умеет только
Ignore / Ping / SlowTo1x / Pause. Авто-возврат скорости запрещён — иначе
йо-йо; возврат к компрессии — всегда действие игрока (как в Sea Power).
После срабатывания — кулдаун (~10 с) на повторное срабатывание той же или
меньшей severity; Pause пробивает кулдаун Slow.

**P4. Компрессия — best-effort, SimDt неприкосновенен.** 16×/32× = больше
фиксированных тиков за кадр, никогда не изменение шага. Если сим-время кадра
превышает бюджет (~24 мс), `Advance` останавливается раньше — фактическая
скорость проседает, топбар показывает это честно (`16x (cpu)`). Смерть-спираль
рендера исключается по построению.

**P5. Линейка живёт на карте и только на карте.** Карта — командная
поверхность; вопросы видимости в 3D закрывает V-hold. Один инструмент — один
дом. Дистанция (м) + пеленг (град, N=0, по часовой). Опционально (если
дёшево): подкраска дистанции относительно максимальной дальности оружия
текущего выделения — это их «линейка vs дальность ракеты» одним взглядом.

**P6. Звуковые сигналы — синтез, не ассеты.** Короткие процедурные тоны
(`LoadWaveFromMemory` / генерация сэмплов при буте), свой паттерн на класс
события, через существующий `AudioManager`. Rate-limit per-kind (~2 с).
Голосовой радио-слой («Contact!», «Taking fire!») — НЕ здесь, это Phase 24
(звуковая система) — ему нужны ассеты и каст.

**P7. Карточка-ТТХ — проекция spec-таблиц, не энциклопедия.** Read-only
рендер существующих `WeaponSpec` / `VehicleSpec` (дальность, урон,
vs-класс множители, скорости, броня по секторам). Один клик вглубь из
Inspector-строки, никакого гиперссылочного графа, никакой исторической
справки. Строки — ASCII (шрифт без кириллицы, `runtime UI English-only`).

**P8. Настройки матрицы персистятся в UI-стейте, не в мире.** Живут рядом с
layout'ом (тот же json, что сохраняет `shutdownUI`), в снапшот мира не входят —
это предпочтение игрока, не состояние сима.

## Майлстоуны

### M1 — Матрица авто-реакции + click-to-fly (ядро фазы) ✅

- Таблица `EventKind → Reaction{Ignore, Ping, SlowTo1x, Pause}`.
  Дефолты: `EnemyContact → SlowTo1x`, `KIA → SlowTo1x`,
  `SuppressionStart → Ping`, `OrderFailed → Ping`, `OrderCompleted → Ignore`.
- Frame-side скан новых записей `EventLog` (курсор по Head), max-severity за
  кадр, кулдаун по P3. Реакция трогает только `App.TimeScale` /
  `LastNonZeroScale` + пинг.
- При срабатывании — строка-баннер у топбара: `AUTO: contact — slowed to 1x`
  (кликабельна → fly-to-Pos). Исчезает по клику или таймеру.
- Click-to-fly из лог-панели: клик по записи центрирует карту (и 3D-якорь?)
  на `EventEntry.Pos` — комментарий в `components/event.go` это и обещал.
- UI конфигурации: компактный ряд чипов в хедере event-log панели
  (клик циклит Ignore→Ping→Slow→Pause). Отдельная панель не нужна.
- Персист по P8.

### M2 — Компрессия 16× / 32× (после M1, см. P1) ✅

- `nextTimeScale`: цикл 1→2→4→8→16→32. Топбар и лейбл `speed x32` уже
  форматируются из `TimeScale` — правка минимальная.
- Адаптивный бюджет по P4: замер сим-времени кадра (у `App.Advance` уже есть
  время тиков в профайлере), обрыв цикла тиков по бюджету, индикация
  `(cpu)` в топбаре.
- Проверка руками: марш конвоя через полкарты на 32× + вспышка боя →
  авто-слоудаун срабатывает раньше, чем игрок успел бы заметить глазами.

### M3 — Звуковой событийный слой ✅

- Генерация 4-5 коротких тонов при буте (разные паттерны: contact — двойной
  писк, KIA — низкий одиночный, suppression — короткая трель, order failed —
  нисходящий интервал). Регистрация в `AudioManager.RegisterWave`.
- Хук в тот же скан M1 (одно место дергает и TimeScale, и звук, и баннер).
- Rate-limit per-kind ~2 с; глобальный мьют-тумблер (чип в хедере event-log,
  персист по P8).

### M4 — Линейка на карте ✅

- Hold-`L` + LMB-drag на map-панели: линия + лейбл `dist 640 m / brg 042`.
  (`L` = line; `B` оказалась занята интерьерами зданий в 3D, R — Roofs,
  N — TerrainDetail.)
- Отпускание LMB замораживает измерение до отпускания `L` (можно прочитать
  не дрожа); отпускание `L` убирает.
- Опция P5: если в выделении есть стрелки — подкраска лейбла
  (в дальности / вне дальности лучшего ствола выделения).
- Чисто map-render, ноль ECS.

### M5 — Карточка-ТТХ ✅

- Клик по строке оружия в Inspector (юнит/техника) → флоатер-карточка:
  `WeaponSpec` (range / RoF / damage / vs Soft-Light-Heavy).
- Клик по классу техники → `VehicleSpec` (скорости road/offroad/reverse,
  turn radius, броня по секторам, сенсоры/шум, loadout).
- Реюз `ui/widget.go` примитивов (Header / TextRow / Bar), режим read-only,
  один уровень глубины (из карточки техники по клику на ствол — карточка
  оружия, и это всё).

Порядок: M1 → M2 жёстко (P1); M3 после M1 (общий скан); M4, M5 — независимы,
можно в любой момент.

## Не в этой фазе (адреса)

- **Маркеры/аннотации на карте** → Phase 21 (marker context menu,
  `COMMAND-MODEL.md` §6) — там же polyline/arc placement.
- **Рандеву по времени** (точка сбора + синхронное прибытие нескольких
  отрядов с авторасчётом скоростей) → Phase 21 multi-squad coordination,
  поверх joint-barrier инфраструктуры Phase 20. Sea Power подтверждает
  ценность; у нас для этого уже задуман фундамент (OrderGroup + barriers).
- **Голосовой радио-канал** → Phase 24 (звуковая система).
- **EMCON / управление эмиссиями сенсоров** (радар включён = видишь дальше,
  но светишься) → расширение модели `Sensors`, когда появится техника с
  активными сенсорами (Phase 20+). Осмысленно, но требует sim-изменений —
  вне рамки этой фазы по определению.
- **Полная энциклопедия с гиперссылками** — не берём вообще: наш жанр не
  про фетиш матчасти; карточка-ТТХ (M5) закрывает практическую потребность
  «почему мой ПКМ не берёт БТР».
- **Уровни сложности с подглядыванием за противником** — отвергнуто:
  FoW всегда сенсорный, доступность решаем объяснимостью, не читами.

## Отклонения от плана (по факту реализации 2026-08-09)

**1. Событие `EventEnemyContact` никто не писал** — вид был объявлен в
`components/event.go` с самой Phase 15.C, но ни одна система его не пушила
(пишутся только KIA / Suppression / OrderCompleted / OrderFailed). Без него
M1 беззубый: «замедлиться на первом контакте» — ЕДИНСТВЕННАЯ причина, по
которой фаза существует. Поэтому одна правка в симе всё же понадобилась:
`ContactSystem.pushContactEvent` при создании нового Contact'а, только для
наблюдателя-игрока. Лог для сима write-only (ни один читатель в симе), так
что поведение не меняется — и это доказано: `replay_baseline.sh` даёт
55/55 IDENTICAL с этой правкой. **`MapPingContact` осознанно НЕ спавним**:
пинг — это ECS-сущность, её создание сдвинуло бы раздачу entity ID и все
хеши реплея. Хвост: контактный пинг на карте — когда будет повод
пере-снять базлайн.

**2. `ReactPing` → `ReactNotify`, без спавна пинга.** По той же причине:
слой внимания живёт во второй половине кадра, вне тика, и не имеет права
создавать сущности. Notify = баннер + звук. Существующие пинги (KIA)
продолжает спавнить сим, как и раньше.

**3. Панель событий понадобилась целиком.** План говорил «чипы в хедере
event-log панели, отдельная панель не нужна» — но панели не существовало:
лог был хвостовой секцией ПУСТОГО инспектора, то есть исчезал, как только
что-то выделено. Ровно во время боя его не видно. Заведён виджет
`PanelEvents` (чипы матрицы + тумблер звука + кликабельные строки
fly-to). Строка события вынесена в общий `ui.DrawEventRow`, так что
хвостовой список в инспекторе получил fly-to бесплатно.

**4. Линейка на `L`, не на `B`.** `B` занята переключением интерьеров
зданий в 3D. Фокус панели их бы развёл, но одна клавиша с двумя смыслами —
мина под будущее изменение правила фокуса. `L` = line, свободна.

**5. M3 оказался больше, чем «хук в AudioManager».** Аудиоустройство в
проекте не инициализировано вообще, `NewAudioManager` / `RegisterWave` —
мёртвый код без единого вызова. Сделан самостоятельный слой
`audio_cues.go`: `InitAudioDevice` под гейтом `!headless`, синтез 5 тонов
в WAV-образ в памяти, `LoadWaveFromMemory`, rate-limit 2 с на вид события,
тумблер mute. `AudioManager` не трогали — он про пространственный звук
мира, это другая задача.

**6. Строка оружия юнита в инспекторе показывала ID сущности** (`Primary:
#3F1A`) — нечитаемо и бесполезно. Заменена на имя + боезапас, попутно
стала входом в карточку ТТХ.

**7. Прайминг сканера чинился отдельно.** Первая версия ставила
`primed = true` на первом скане НЕПУСТОГО лога — то есть на пустом при
старте логе прайм откладывался до первого события, и это событие
проглатывалось. Первое событие сессии — ровно то, ради которого фаза
существует. Теперь прайм происходит на первом же кадре, даже с пустым
кольцом (`newestEventAt` = 0).

## Хвосты фазы

- **Контактный `MapPing` на карте** — вид `MapPingContact` объявлен и не
  используется; спавн сущности из сима сдвинет entity ID и потребует
  пере-снять `.claude/baseline/replay`. Делать заодно с любой другой
  правкой, которая и так двигает базлайн.
- **Баннер не обновляется под кулдауном** — во время боя второе и
  последующие события той же громкости в 10-секундном окне дают звук, но
  не освежают текст баннера. Осознанно (баннер-спам хуже), но если на
  плейтесте будет мешать — развести кулдаун реакции и кулдаун баннера.
- **Голос и EMCON** — адреса выше, в «Не в этой фазе».
