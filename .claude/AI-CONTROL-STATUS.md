# ИИ и управление: что задумано против того, что стоит

Сверка на **2026-08-25**, после Phase 20 M3. Документ существует, потому что
поведение и управление росли восемью фазами вперемешку и перестали читаться
целиком: `GAMEDESIGN` говорит, что мы хотим, `COMMAND-MODEL` — как это устроено,
`ROADMAP` — в каком порядке, но ни один из трёх не отвечает на вопрос **«что уже
работает прямо сейчас»**. Здесь только это.

Легенда: ✅ работает · 🟡 частично (написано ниже, чего не хватает) · ❌ нет кода ·
💀 код есть, читателя нет.

Поддерживать так: закрывая майлстоун, править СТРОКИ ТАБЛИЦ, а не дописывать
абзацы в конец. Документ должен оставаться на две страницы таблиц плюс хвост.

## 1. Картина на одной странице

Мы строим два ортогональных каркаса. **Иерархия ИИ** — кто принимает решение и
как часто. **Слои управления** — как игрок выражает намерение. Ниже — обе оси со
статусом.

### Иерархия ИИ (архитектурное решение №9 в ROADMAP)

| Ярус | Такт | Что должен решать | Статус | Где живёт |
|---|---|---|---|---|
| Стратегический | 10-30 с | что делает фракция: куда наступать, что оборонять, кого куда посылать | ❌ **нет вообще** | планируется 22-lite → 22 |
| Оперативный | 1-5 с | КАК отряд исполняет уже выданный приказ | 🟡 три режима | `squad_brain.go` |
| Тактический | каждый тик | что делает боец / корпус / борт прямо сейчас | ✅ плотно | 12 систем, см. §3 |

**Главный вывод сверки:** верхнего яруса нет физически. Никто, кроме игрока,
сцены и одной строки в `boot_scene.go`, не выдаёт приказ. Всё, что делает
противник, — это РЕАКЦИЯ на то, что с ним происходит. Отряд под огнём залегает,
перебегает, отвечает; корпус ставит дым и пятится; борт отстреливает ловушки —
но никто не решает «атаковать высоту 3».

### Слои управления (COMMAND-MODEL §2)

| Слой | Что это | Статус | Чего не хватает |
|---|---|---|---|
| 1. Orders — императивные глаголы | 9 видов из ~20 задуманных | 🟡 | Retreat / Mount / Build / Follow / Escort и joint-приказы |
| 2. Standing rules — постоянные настройки | Movement / Engagement / Behavior / Doctrine / Autonomy | ✅ почти всё | пер-юнитовый override в UI, два мёртвых поля |
| 3. Per-weapon intent — «этим стволом по этой цели» | — | ❌ | весь слой: `OrderParamWeaponPref` = 0 упоминаний в коде |

## 2. Слой 1 — Приказы

### Что стоит

Каркас закрыт и не менялся с Phase 11: `Order` — отдельная сущность, очередь —
связный список через `OrderChain.Next`, голова на `OrderQueueHead`, per-kind
завершение через спек-таблицу (`components/order_spec.go`), тумбстоуны в
`OrderHistory` для таймлайна.

| Вид приказа | Статус | Завершение |
|---|---|---|
| MoveTo | ✅ | по радиусу прибытия |
| Garrison | ✅ | все на этаже |
| OccupyBuilding | ✅ | все на этаже |
| ClearBuilding | ✅ | нет живых врагов внутри + свой внутри; авто-цепочка в OccupyBuilding |
| OccupyTrench | ✅ | по радиусу |
| DefendPosition | ✅ | никогда (только отмена) |
| Patrol | ✅ | по радиусу, авто-переиздание для петли |
| AttackTarget | ✅ | смерть цели / 8 с вне досягаемости |
| SuppressFire | 🟡 | таймер 30 с; **в UI здания пункт выключен** |
| Retreat | ❌ | — |
| Mount / Disembark | ❌ | нужен barrier (см. ниже) |
| Build (окоп / мешки / мины) | ❌ | Phase 21 Engineering |
| Follow / Escort / Heal / Repair | ❌ | — |
| DisperseOnLine | ❌ | — |
| Demolish / BurnBuilding | ❌ | — |

### Чего нет в механике приказов

- **Joint orders и барьеры** — `OrderJoint`, `BarrierKind`, `OrderGroup`: **ноль
  кода**. `OrderGroup` упомянут в одном комментарии и не объявлен. Это ближайшая
  жёсткая зависимость: Phase 20 M4 (высадка десанта) без барьера не делается, и
  Phase 20.5 (посадка пехоты на БТР) переиспользует тот же механизм.
- **`OrderStateBlocked` — состояние-призрак.** Объявлено, рисуется инспектором и
  таймлайном тремя местами, но **ни одна система его не выставляет**. Либо
  завести писателя (нет пути / цель пропала / радиосвязь потеряна), либо убрать
  из UI, чтобы не обещать игроку индикацию, которой не будет.
- **`OrderTrigger`** (условные приказы «при контакте → перейти в AttackMove») —
  задел из GAMEDESIGN §3, кода нет.
- **Приказ, адресованный юниту внутри отряда.** Одиночник командует собой с
  Phase 20.7 L0 (`ensureCommandable`), сегодня M3 обобщил и правила огня на
  «командир = отряд ИЛИ сам». Внутри отряда пер-юнитового приказа по-прежнему
  нет; ближайший суррогат — `IndividualPosition` (Shift+ПКМ по подмножеству).
- **Редактирование плана**: вставка / удаление / перетаскивание точки маршрута,
  контекстное меню на маркере приказа, undo/redo. Ничего нет; таймлайн — только
  чтение.

## 3. Тактический ярус — что реально решает за бойца

Это самая плотная часть проекта. Порядок — по конвейеру тика.

| Система | Решает | Статус |
|---|---|---|
| `contact` | кто кого видит / слышит / перехватывает по излучению | ✅ сенсорные каналы, ESM-пеленги, FoW, терраин-LOS |
| `weapon` | по кому и чем стреляем | ✅ RoE-гейт, фокус по приказу, классы, секторная броня, воздушная ветка |
| `threat` | насколько страшно и откуда | ✅ DangerBuffer → Threat + кластеры направлений + `UnsafeArea` |
| `utility_evaluator` | режим бойца (8 режимов) | 💀 **см. ниже** |
| `stance_controller` | стоя / присев / лёжа | ✅ по `Threat.State` |
| `survival_instinct` | куда деться под огнём | ✅ скоринг ПОЗИЦИЙ, `TacticalOverride`, ScatterProtocol |
| `vehicle_reflex` | рефлекс корпуса | ✅ FaceThreat / SmokeAndReverse / Flee / GoDark |
| `air_reflex` | рефлекс борта | ✅ Break / Flare / Abort |
| `micro_path` / `orca` / `nav_service` | как дойти, никого не снеся | ✅ A* по мультиграфу, ORCA, стили пути |
| `formation` / `squad_macro_path` | где место каждого в строю | ✅ слоты, темп колонны, реформация на ходу |

### Единственная крупная дыра здесь

**`UtilityEvaluator` считает режим, который почти никто не читает.** Восемь
режимов объявлено, шесть включено, скоринг с гистерезисом и текстовой причиной —
и ровно **два потребителя**: `shouldFire` (Reloading / Suppressed глушат огонь) и
`stance_controller` (Suppressed → лёжа). Комментарий на `ActionMode` обещает, что
режим читают «MicroPath, StanceController, WeaponSystem» — `MicroPath` не читает
его вообще.

Фактическое поведение производит связка `SquadBrain` + `SurvivalInstinct` +
рефлексы, а не режим. Это не баг, это расслоение: сначала написали Utility, потом
поверх выросли скорер позиций и мозг отряда, и Utility остался сбоку.

Два честных выхода, выбрать один: **(а)** дать режиму настоящих потребителей —
Engaging останавливает сближение, Repositioning владеет очередью, Reloading
запрещает движение; **(б)** признать, что режим — это ЯРЛЫК для игрока и гейт
огня, ужать спеки до реально работающих и убрать обещание из комментария. Пока
живём в состоянии «есть, но не решает», и это главный источник ощущения
разрозненности в поведении.

## 5. Слой 3 — Целеуказание оружию

**Не начат.** `OrderParamWeaponPref` — ноль упоминаний. Нет aim-режима курсора,
нет клика «этот ствол → эта цель», нет выключения отдельного ствола.

Половина работы при этом уже лежит: `squad bar` знает свои стволы, показывает
боезапас, карточки кликабельны через request-паттерн; `spec card` объясняет, чем
эта пушка не берёт тот корпус. Не хватает именно глагола.

## 7. Что оказалось не тем, чем записано

Эти пять пунктов — прямая причина ощущения «теряю картину». Их стоит поправить
в исходных документах, иначе сверка будет расходиться дальше.

1. **ISSUES #28 устарел наполовину.** «AttackTarget не наводит огонь» — закрыто в
   19.5 MC3 (`focusTarget` в `weapon_fire_gate.go`: названная цель выигрывает,
   пока проходит обычные гейты). «Приказы только отрядные» — закрыто для
   одиночников в 20.7 L0 и обобщено сегодня в M3. От #28 осталось ровно:
   пер-оружейное предпочтение и приказ юниту ВНУТРИ отряда.
2. **Матрица авто-паузы (COMMAND-MODEL §8, «Phase 21») сделана** — как
   `AttentionMatrix` в 19.7, с четырьмя реакциями вместо тумблеров.
3. **`VehicleSystems` из §4 не будет** — техника получила рефлексы из спека, это
   работает лучше набора тумблеров. Документ стоит поправить, а не код.
4. **`OrderStateBlocked` рисуется, но не наступает** — UI обещает то, чего
   симуляция не производит.
5. **`RadioNetwork` и `Occupancy`** — данные пишутся, потребителя нет. Обе
   помечены как задел под Phase 21 (связь и общий ledger укрытий).

## 8. Что делать дальше — по зависимостям, а не по желанию

Три вещи, в этом порядке. Обоснование — не «важность», а то, что одно блокирует
другое.

**Первое. Барьеры и joint-приказы.** Это единственная механика, которой не
хватает *физически*, и она уже блокирует запланированное: Phase 20 M4 (десант с
вертолёта) без неё не делается, Phase 20.5 (пехота на БТР) — тот же механизм,
Phase 21 (сложные планы) на нём же. Объём небольшой: `OrderJoint{Participants,
BarrierKind}` + арм в резолвере + отмена каскадом. Всё остальное в очереди
приказов под это готово.

**Второе. Определиться с Utility.** Пока режим бойца не решает ничего, любая
новая тактическая фича будет писаться мимо него — как уже написались мозг отряда
и инстинкт. Это не фаза, а решение на полдня: либо дать читателей, либо ужать.
Сделать ДО стратегического ИИ, иначе бот будет строиться поверх слоя, про
который непонятно, живой он или нет.

**Третье. Оперативный бот (22-lite).** Самая большая дыра между «хотим» и «есть»,
но она не блокирует ничего, кроме удовольствия от игры. Исполнительный слой под
него уже стоит: `SquadService.IssueOrder` принимает любой вид, `SquadBrain`
исполняет, реактивный ярус спасает бойцов. Боту остаётся выбирать цель и
адресата — то есть ровно то, чего сейчас не делает никто.

Phase 21 (per-weapon intent, редактирование плана, инженерка) идёт после и
разбирается на куски независимо.
